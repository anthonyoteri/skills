# Standards reviewer

Read the repo's coding and review standards: `CONTRIBUTING.md`, `AGENTS.md` / `CLAUDE.md`, style guides, linter and formatter configs, PR and commit rules, `CODEOWNERS`, and the conventions the existing code follows. Then find every place the spec, followed literally, would make an implementer break one: naming, layout, error handling, dependencies, test conventions, commit and PR format, required approvals or labels.

Quote the rule and the spec text that conflicts with it. If the rule should change instead, say so in `Fix`.
