# Problem reviewer

Read the references that describe the behavior the spec sets out to change: bug reports, feature requests, incidents, discussions, failing tests. Then answer: once every ticket is implemented in full, is the problem solved?

- **Root cause**: the spec fixes the cause the references point to, not a symptom.
- **Every reported case**: each scenario, reproduction and affected user in the references is covered by the spec, or explicitly scoped out with a reason.
- **Acceptance**: the spec states how to tell the problem is gone, in terms the reporter would accept.
- **No drift**: the spec's goal matches what the references ask for; work they don't ask for is called out as scope.
